# 운영 전 필요한 사업 데이터

검색 범위는 애플리케이션 코드, 설정, 데이터, 문서와 공개 자산이다.
`lorem`, `FIXME`, `href="#"`, 예시 네이버 링크, 가격, 임의 치수·재질·인증
주장은 발견되지 않았다.

Phase 3부터 운영 데이터는 `src/config/site.ts`를 직접 수정하지 않고
`data/launch/`의 다섯 개 비템플릿 입력 파일로 관리한다. `.template` 파일은
사람이 작성하기 위한 가이드이며 운영 데이터로 자동 로드되지 않는다.

```bash
npm run import:launch-data
npm run validate:preview
npm run validate:launch
```

가져오기는 검증된 입력을 `data/launch/launch-data.json`으로 정규화한다.
원본 카탈로그 근거는 유지되고, 확인된 수정만 명시적 오버라이드로 적용된다.

## 1. Brand

| 필요한 값                  | 표시 위치                               | 필요한 이유와 허용 형식                        | 출시 차단 |
| -------------------------- | --------------------------------------- | ---------------------------------------------- | --------- |
| 한글 브랜드명              | `business.yaml`, 헤더, 푸터, 메타데이터 | 공식 상호 또는 소비자 브랜드의 한글 문자열     | 예        |
| 영문 브랜드명              | 설정, 헤더 보조 표기                    | 공식 대소문자와 띄어쓰기를 포함한 영문명       | 예        |
| 로고                       | `logoPath`, 현재 미사용 SVG 자산        | SVG 또는 충분한 해상도의 투명 PNG와 사용 지침  | 예        |
| 이미지 내 HOYANG 표식 관계 | HG 제품 이미지                          | 브랜드 소유·유통 관계 및 이미지 사용 권한 확인 | 예        |

`브랜드명`, `BRAND NAME`은 사업 데이터가 필요한
의도적 설정 플레이스홀더다.

## 2. Company and legal information

| 필요한 값           | 표시 위치               | 필요한 이유와 허용 형식                 | 출시 차단            |
| ------------------- | ----------------------- | --------------------------------------- | -------------------- |
| 회사명·대표자       | 푸터, 법적 페이지       | 사업자등록증과 동일한 문자열            | 예                   |
| 사업자등록번호      | 푸터                    | `000-00-00000` 형식                     | 예                   |
| 통신판매업 신고번호 | 푸터                    | 관할 기관의 공식 신고번호               | 판매 링크 운영 시 예 |
| 사업장 주소         | 푸터, 문의              | 도로명 주소와 필요한 상세 주소          | 예                   |
| 고객센터·이메일     | 푸터, 문의, 법적 페이지 | 실제 운영 전화번호와 수신 가능한 이메일 | 예                   |
| 개인정보 보호책임자 | 개인정보처리방침        | 담당자 이름 또는 직책                   | 예                   |

현재 `정보 준비 중` 표시는 모두 중앙 launch data에서 공급되며 사업 데이터가
입력되기 전까지 프리뷰에서만 유지해야 한다.

## 3. Product catalog

| 필요한 값                   | 표시 위치           | 필요한 이유와 허용 형식                        | 출시 차단                |

| `무광` 공식성               | 마감 필터와 HG 제품 | 공식 마감명인지 내부 파일 표기인지 확인        | 해당 필터 정확성 차단    |
| 제품 치수·재질·설치법       | 상세 하단           | 검증된 단위 포함 값과 공식 설치 문서           | 비차단, 정보 완성도 영향 |

`상세 정보 준비 중`은 확인되지 않은 사양을 만들지 않기 위해 의도적으로
유지한다.

## 4. Naver Store

| 필요한 값       | 표시 위치                 | 필요한 이유와 허용 형식                                                          | 출시 차단               |
| --------------- | ------------------------- | -------------------------------------------------------------------------------- | ----------------------- |
| 스토어 홈 URL   | 헤더, 모바일 메뉴, 홈 CTA | 실제 `https://smartstore.naver.com/...` URL                                      | 구매 목적 사이트에는 예 |
| 변형별 상품 URL | 제품 상세 구매 버튼       | 마감별 실제 판매 상세 URL                                                        | 해당 변형 구매 차단     |
| 판매 상태       | 제품 상세                 | `active`, `inactive`, `coming-soon`, `inquiry-only`, `unverified` 중 검증된 상태 | 해당 변형 구매 차단     |

URL이 없을 때 `판매 링크 준비 중`은 링크가 아닌 비활성 요소다. `#`,
`example.com` 또는 가짜 네이버 URL은 사용하지 않는다.

## 6. Images and documents

| 필요한 값                     | 표시 위치    | 필요한 이유와 허용 형식                    | 출시 차단 |
| ----------------------------- | ------------ | ------------------------------------------ | --------- |
| 고해상도 HG 원본              | HG 카드·상세 | 제품 전체가 포함된 무손실 또는 고품질 원본 | 비차단    |
| 설치 공간 사진                | 제품 상세    | 실제 설치 사례이며 사용 권한이 확인된 사진 | 비차단    |
| 제품 도면·설치 문서           | 제품 상세    | 모델·개정일이 확인된 PDF 또는 이미지       | 비차단    |
| 최종 브랜드 라이프스타일 사진 | 홈, 브랜드   | 실제 브랜드 촬영본                         | 비차단    |

`bathroom-architecture-placeholder.png`, 홈의 provisional 표기, 설치 사진·도면
준비 상태는 의도적으로 유지한다. 사용하지 않는 기존 컬렉션 SVG와 변형 SVG는
실제 파일 매핑 실패 시의 안전한 대체 자산으로 유지한다.

## 7. SEO and domain

| 필요한 값       | 표시 위치                      | 필요한 이유와 허용 형식                | 출시 차단 |
| --------------- | ------------------------------ | -------------------------------------- | --------- |
| 실제 사이트 URL | canonical, sitemap, robots, OG | HTTPS 운영 도메인                      | 예        |
| 최종 OG 이미지  | 소셜 공유                      | 1200×630 권장, 브랜드 사용 승인 이미지 | 비차단    |
| 검색 노출 문구  | 페이지 메타데이터              | 확정 브랜드명과 검증된 설명            | 예        |

`.env.example`과 설정의 `https://example.com`은 로컬 개발용 의도적 기본값이다.
운영 배포에서는 `NEXT_PUBLIC_SITE_URL`과 가져온 canonical origin이 일치해야
하며 `NEXT_PUBLIC_SITE_RELEASE_MODE=production`을 명시해야 한다.

## 8. Legal review

| 필요한 값               | 표시 위치   | 필요한 이유와 허용 형식                    | 출시 차단 |
| ----------------------- | ----------- | ------------------------------------------ | --------- |
| 개인정보처리방침 최종본 | `/privacy`  | 실제 수집·위탁·보유 정책을 반영한 검토본   | 예        |
| 이용약관 최종본         | `/terms`    | 외부 판매 채널과 책임 범위를 반영한 검토본 | 예        |
| 이미지·상표 사용 권한   | 전체 사이트 | 원본 사진과 이미지 내 상표의 게시 권한     | 예        |

현재 법적 페이지의 `초안`, `검토 필요`, `시행일 입력 필요` 표시는
의도적으로 유지한다. 법률 및 사업자 검토 전에는 최종 정책으로 표시하면 안
된다.

## 검색상 문제 없음

- Lorem ipsum, `TODO`, `FIXME`
- 가짜 가격, Offer 구조화 데이터
- 코드에 입력된 임의 치수·재질·성능·인증·수상 주장
- 동작하는 것처럼 보이는 빈 구매 링크
